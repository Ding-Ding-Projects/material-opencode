Web app in Docker

Run it

From a checkout of the repository:

hosting/host.sh            # macOS and Linux
hosting\host.bat           # Windows with Docker Desktop

The script starts the container, waits until the app answers, then prints the address to open on your network. Docker with Compose must be installed. If the app does not answer within two minutes the script says so and points to docker logs.

The interactive setup

The first run starts a setup that asks for:

  1. Instance name, used for the container and its data volume.
  2. Port on this computer (default 4096).
  3. Listen address (0.0.0.0 is the whole local network).
  4. The folder with your projects, mounted at /workspace.
  5. The image: the published one or a local build tag.

Press Enter to keep each default. It also creates a server password and writes everything to hosting/.env, which holds the password, so keep that file private. You can run the setup alone with bun hosting/setup.ts, or --yes to accept every default.

Options

  • --ssh user@host runs it on another machine with Docker. The script copies compose.yaml and .env there over SSH.
  • --build builds the image from your checkout instead of pulling ghcr.io/ding-ding-projects/material-opencode.
  • --down stops and removes the container. Your data volume is kept. It combines with --ssh.

Signing in

Sign in with the password from hosting/.env. The user name is opencode for API clients. The Deploy desktop app can do all of this with buttons.
